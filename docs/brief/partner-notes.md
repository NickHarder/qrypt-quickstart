## The partner project

**Build the Randomness Audit & Integration CLI (the FDE brief), and request a token today.** All four briefs (updated 10/12/2026) are Mid-tier, 2-day take-homes graded on a 100-point rubric with a pass mark of 70. Each caps live API use at 10,240 KiB, requires tests to run against a mock and asks for an AI usage log. With the interview on Wednesday at 1:30, build Saturday to Monday and polish on Tuesday. The [EaaS docs](https://docs.qrypt.com/eaas) say tokens come from contacting Qrypt, and the portal's registration page wouldn't load for me (it's a JavaScript app). Ask your Gauntlet program contact for an assessment token now, and start against a mock, since scanning needs no entropy. The portal gives this brief 1–2 days and the attachment says 2, so plan for 2.

**What it really tests:** whether you can walk into a customer's repo, earn the security lead's trust, and change their code without breaking it. The brief's premise is that "every enterprise security review gates the deal". The report is the artifact the customer signs off on, and the illustrative saving cuts FDE time from about 40 hours to about 6 per customer.

- **Structure:** a Python CLI built as parser → finding model → classifier → reporters → patcher, as the brief requires. Use `ast` with an import-alias table for each file so that `from random import randint as r` and `np.random.*` resolve. Comments never reach the AST and strings are only constants, so neither can produce a call match.
- **Classifier:** deterministic rules first, because `--no-llm` is the CI mode. Look at variable names (token, password, otp, nonce, session, key, salt), the enclosing function and the file path (tests/, sim/). Calls to `secrets` and `os.urandom` are info, with "optional upgrade to Qrypt". One point worth stating in your report: for seeded simulation code, recommend seeding once from Qrypt and recording the seed rather than replacing every call, because replacing them breaks reproducibility. The Monte Carlo brief rests on the same logic.
- **Beat a baseline:** Ruff's [S311 rule](https://docs.astral.sh/ruff/rules/suspicious-non-cryptographic-random-usage) (ported from flake8-bandit) flags weak random-number calls, and its docs describe no way of telling security-sensitive calls from others. Run it on your fixture corpus and put its precision next to yours. That single table shows why the tool exists.
- **Integration:** `qrypt_random.py` uses only the standard library (urllib, json, base64, threading). It pools entropy, uses rejection sampling for ranges, keeps the signatures of the functions it replaces and fails closed with a clear message. `plan` writes a read-only diff. `apply` changes only the ids listed in approvals.yaml, as one commit. `verify` runs the stand-in repo's tests before and after against a local mock. Pick a stand-in repo of at least 10k lines whose tests run in minutes and that uses `random` somewhere token-like, and a separate 100k+ line repo for the speed benchmark.
- **What impresses:** meeting the stated targets, reproduced by a metrics script in CI: detection recall ≥95%, precision ≥90% and correct class ≥85%; a 100k-line scan in under 30 s using under 500 MB; under 5 minutes from install to first report; and an adapter p95 under 5 ms. Add a README "Data handling" section, a test proving secrets are redacted, and an executive summary that a non-engineer has actually read and explained back to you. The cheap stretch goals that match your record are SARIF output and `--fail-on high`.
- **If you take on another brief:** for the *MCP server*, reuse this pool and sampler, read stdio credentials from the environment, never pass the Qrypt token through ([MCP spec](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)), and write a test proving no byte offset is served twice. For *Monte Carlo*, derive worker seeds with `SeedSequence.spawn`, not seed+i ([NumPy](https://numpy.org/doc/stable/reference/random/parallel.html)), and sum shards in index order so replays come out bit-identical. Note that new AWS Free-plan accounts close after 6 months or when the credits run out ([AWS](https://aws.amazon.com/free/)). For the *quickstart*, the friction is real: the docs' curl, Python and PowerShell examples omit the required `Accept` header, docs.qrypt.com has no [llms.txt](https://llmstxt.org/) (404 in Oct 2026), and the only SDK quickstart is for [C/C++](https://docs.qrypt.com/sdk/quickstarts/).

## Engineering & tech stack

- **Languages:** Rust is primary, with C++ and Python secondary ([Backend](https://www.builtinaustin.com/job/backend-software-engineer-ai-native/10487707), [Senior Backend](https://jobs.lever.co/qrypt/24628652-6650-4556-b744-1b6318a6a0d0)). - **Cloud:** AWS infrastructure as code in Terraform, plus containers and Kubernetes. The team deploys "the cloud interface into customer-controlled environments" with portable IaC, and runs observability and on-call ([Senior Cloud Engineer](https://jobs.lever.co/qrypt/545ce743-5432-43b7-a097-e0846ed124ea)).
- **APIs:** REST with bearer tokens from the portal (the portal also lists OAuth), plus metered quotas and rate limits ([docs](https://docs.qrypt.com/eaas)). The AWS listing claims 1.575 Gbps of entropy throughput, which is a vendor figure.
- **Edge and network work:** custom Yocto kernels for Jetson (Orin Nano moved from Linux 5.15 to 6.6), a strongSwan IPsec plugin on BlueField DPUs, and key injection into VPP/WireGuard (qp-vpp, with a live dashboard on AWS).
- **AI-native expectations:** every posting requires daily use of agentic tools and full ownership of whatever the AI produces, and asks hires to help set the team's instruction conventions and review standards. Mandich's [April post](https://www.qrypt.com/resources/the-mythos-moment-ai-exposed-what-was-already-there/) says a **native Claude Code integration is coming**.
- **How the projects fit:** the audit CLI and the quickstart work on the developer surface. The MCP server ties into the Claude Code and agents push. The Monte Carlo platform covers AWS scaling and the "entropy for statistical analysis" use case from the AWS listing. Together they hit the portal's focus areas: customer-facing solutions, modernization, and scaling and reliability.

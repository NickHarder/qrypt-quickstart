# NS-01: Activation, signup to first successful call

Measured: not yet. No run has produced a value.

| Field | Value |
|---|---|
| Name | Activation: signup to first successful call (funnel stage 3) |
| The promise it proves | UC-01 (from a token to a first key) and UC-02 (the error a developer is staring at gets fixed): a developer new to Qrypt gets a working call in their first week |
| Definition and formula | Accounts of the cohort whose `entropy_first_success` has `occurred_at` ≤ signup + 7 days ÷ accounts of the cohort |
| Unit and aggregation window | A share of **accounts**; cohort = accounts created in one ISO week (UTC); read 7 days after the week ends |
| Data source, and where it is computed | `entropy_first_success`, emitted by Qrypt's API; the denominator from Qrypt's portal account records; joined on `account_ref` in Qrypt's analytics ([the one specification](/KEY_METRICS.md)) |
| Target, and the reasoning | 50%, from a baseline of 25%: **both the brief's assumptions** (400 signups a quarter → +100 activated developers a quarter), to be validated against real analytics[^assessment] |
| What gaming looks like, and the guardrail | Counting a call nobody meant to keep (a one-off ping from a support engineer's test, a scripted signup that calls once): [GR-01](/metrics/GR-01.md), return within 7 days of activated accounts, falls when activation is hollow |
| What decision changes when it moves | Below 25% for two mature cohorts: the next backlog item is the one that removes the largest stage 2 to stage 3 drop (token help, error pages), ahead of new languages. Above 50%: effort moves from first-run fixes to the return stage |

The specification of every stage is in [the key metrics](/KEY_METRICS.md).[^key-metrics]

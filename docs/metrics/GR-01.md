# GR-01: Return within 7 days

Measured: not yet. No run has produced a value.

| Field | Value |
|---|---|
| Name | Return within 7 days (funnel stage 5) |
| The promise it proves | UC-01: the developer uses the pattern in their own code after the first run |
| Definition and formula | Activated accounts of the cohort (NS-01's numerator) with an `entropy_return_success` at most 7 days after `first_success_at` ÷ activated accounts of the cohort |
| Unit and aggregation window | A share of **activated accounts**, not of the cohort; weekly signup cohort; read 14 days after the week ends |
| Data source, and where it is computed | `entropy_return_success`, emitted by Qrypt's API on the account's first `200` at least 24 hours after its first; computed in Qrypt's analytics |
| Target, and the reasoning | At least 50% of activated accounts: **the project's own assumption**. The 24-hour gap keeps the first session's own repeats out |
| What gaming looks like, and the guardrail | A sample that calls on a schedule, or a reminder that asks for one call: it is the guardrail itself; the check against it is the `client` split, where a schedule shows as one client and one hour |
| What decision changes when it moves | Below 50% for a mature cohort while NS-01 rises: activation is hollow, and the work stops raising NS-01 and asks why developers leave after one call |

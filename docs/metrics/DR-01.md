# DR-01: Landing to signup

Measured: not yet. The beacon is not built (RQ-40).

| Field | Value |
|---|---|
| Name | Landing to signup (funnel stage 1) |
| The promise it proves | UC-01: the quickstart page sends a developer on to a token |
| Definition and formula | Accounts created in week W with `signup_ref = quickstart` ÷ `quickstart_page_viewed` events in week W |
| Unit and aggregation window | A ratio of two weekly counts (page loads, accounts); joined to nothing, so it is not a per-person conversion |
| Data source, and where it is computed | `quickstart_page_viewed`, a cookieless beacon from the quickstart site to Qrypt's collector; `signup_ref` from Qrypt's portal account records; computed in Qrypt's analytics. **The beacon does not exist yet** |
| Target, and the reasoning | 10%: **the project's own assumption**; no landing traffic figure exists to start from, and it is replaced by the first four mature weeks |
| What gaming looks like, and the guardrail | Dropping the beacon from some loads, or counting signups that came from elsewhere: [NS-01](/metrics/NS-01.md) does not rise with it, and [GR-01](/metrics/GR-01.md) falls if the new signups never return |
| What decision changes when it moves | Low: the page's opening (the time target, the token route, DQ-04) is rewritten before anything below it. High with a flat NS-01: the loss is after the token, not on the page |

The event and the rules every stage shares are in [the key metrics](/KEY_METRICS.md).[^key-metrics]

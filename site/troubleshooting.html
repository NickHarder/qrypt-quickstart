HTTP errors from Qrypt

400: malformed request

Symptom

Qrypt answered HTTP 400: malformed request: size must be 1-512.

Likely cause: Qrypt reads the request as a malformed URL or invalid parameters, such as a size outside 1 to 512 or not a whole number.

Fix: send size as a whole number of KiB from 1 to 512; size=1 is enough for one key. Send both headers Qrypt's documentation requires, Accept: application/json and Authorization: Bearer <token>. The quickstart sends both; code you write yourself must too.

401: token invalid or expired

Symptom

Qrypt answered HTTP 401: the token is invalid or expired; get a new one at portal.qrypt.com.

Likely cause: the access token is invalid or has expired. It may also have been pasted with quotes or a space around it.

Fix: generate a new access token for the Entropy service in the Qrypt portal (portal.qrypt.com), or ask your Qrypt contact for one. Replace the line in .env with QRYPT_API_KEY=<token>: no quotes, no spaces. Run the quickstart once.

403: entropy allotment used up

Symptom

Qrypt answered HTTP 403: allotment used up; ask Qrypt.

Likely cause: the account has retrieved its maximum entropy allotment for the current period. This is not the rate limit (that is 429): waiting a few seconds does not help.

Fix: stop sending requests. Ask Qrypt to change the account's limit. Check that your code asks only for what it needs: size=1 is 1 KiB, and size=512 uses 512 times as much.

429: rate limit

Symptom

Qrypt answered HTTP 429: too many requests in a short time; wait 10 seconds, then run once.

Likely cause: the token's requests came too close together, usually from a loop or several scripts sharing one token. Qrypt's docs say the limit is 30 requests in 10 seconds, but a trial key was refused for a second request 0.36 s after its first. Qrypt's answer has no Retry-After header. Unlike 403, it passes on its own.

Fix: wait 10 seconds, then run once. Never retry in a tight loop: each retry counts against the same limit. If you need more entropy, ask for more in one request (up to 512 KiB) instead of making many small ones.

500: Qrypt internal error

Symptom

Qrypt answered HTTP 500: try again shortly.

Likely cause: an error inside Qrypt's service, not in your request.

Fix: run the quickstart again in a minute. If it keeps failing, contact Qrypt support.

503: not enough entropy right now

Symptom

Qrypt answered HTTP 503: try again shortly.

Likely cause: Qrypt's entropy supply is temporarily insufficient.

Fix: run the quickstart again in a minute, asking for size=1 rather than a large size.

Your machine and network

The token is not found

Symptom

Set QRYPT_API_KEY=<token> in .env (Entropy tokens: portal.qrypt.com)

Likely cause: there is no .env file in the folder you ran the quickstart from, or it has no QRYPT_API_KEY line.

Fix: in a text editor, create a file named .env next to the quickstart with the line QRYPT_API_KEY=<token>, and run the quickstart from that folder. Add .env to .gitignore so it is never committed.

The runtime is missing or too old

Symptom: Python prints ModuleNotFoundError: No module named 'cryptography' (or 'dotenv'). Node.js prints TypeError: process.loadEnvFile is not a function or ReferenceError: fetch is not defined.

Likely cause: the packages are not installed, or Node.js is older than 20.12.

Fix: check the versions with python3 --version (3.10 or later) and node --version (20.12 or later), then install what the quickstart needs:

pip install cryptography python-dotenv

pip refuses to install the packages

Symptom: pip install cryptography python-dotenv stops with error: externally-managed-environment.

Likely cause: your Python belongs to the operating system (Debian, Ubuntu, Homebrew), which keeps packages out of it (PEP 668).

Fix: make a virtual environment in the project folder, install the packages there, run the program with its Python, and add .venv/ to .gitignore:

python3 -m venv .venv
.venv/bin/pip install cryptography python-dotenv
.venv/bin/python quickstart.py

A corporate proxy or a certificate error

Symptom: a line that starts Could not get entropy and names a certificate, such as CERTIFICATE_VERIFY_FAILED, SELF_SIGNED_CERT_IN_CHAIN or UNABLE_TO_GET_ISSUER_CERT_LOCALLY.

Likely cause: your network inspects HTTPS traffic with its own root certificate, which your runtime does not trust yet.

Fix: ask your IT team for the company's root certificate file (PEM) and point the runtime at it. Never turn certificate checks off.

SSL_CERT_FILE=/path/to/company-ca.pem python quickstart.py
NODE_EXTRA_CA_CERTS=/path/to/company-ca.pem node quickstart.mjs
SSL_CERT_FILE=/path/to/company-ca.pem cargo run

The Rust program also trusts the operating system's own certificates, so on macOS and Windows a root certificate IT has installed works as it is.

If you must go through a proxy, Python and the Rust program read HTTPS_PROXY on their own. Recent Node.js versions read it when started with --use-env-proxy (see node --help).

No connection, or a timeout

Symptom: a line that starts Could not get entropy and names Connection refused, ECONNREFUSED, ENOTFOUND or a timeout.

Likely cause: no network, a firewall that blocks api-eus.qrypt.com, or a QRYPT_API_URL left pointing at a test server.

Fix: check the network, remove any QRYPT_API_URL line from .env and your shell, and run once more.

Common mistakes in your own code

size counts KiB, not bytes

Symptom: the allotment runs out (403) after a few runs, or the answer holds far more data than you expected.

Likely cause: size=32 was sent to get a 32-byte key. Qrypt reads it as 32 KiB: 32 blocks of 1,024 bytes.

Fix: send size=1 (1,024 bytes) and take the 32 bytes you need from it.

The base64 block was not decoded

Symptom: the key is rejected as the wrong length, or it is made of letters and digits rather than raw bytes.

Likely cause: each block in random is base64 text. Used as it is, it is text, not 1,024 random bytes.

Fix: decode the block first (base64.b64decode in Python, Buffer.from(block, "base64") in Node.js), then take bytes 0 to 31 as the key.

A retry loop faster than the rate limit

Symptom: a run of 429 answers, then possibly a 403.

Likely cause: code that retries at once on any error. Every retry counts against the same rate limit.

Fix: on 429, wait at least 10 seconds before one more try. On 403, stop. On 500 or 503, wait a minute.

Handling the key safely

  • Never print, log or commit the key, and never write it to a file the quickstart does not need. The quickstart keeps it in memory only.
  • Never commit the token either: keep it in .env, and keep .env in .gitignore. Never show it in a screenshot, a recording or an AI agent's chat.
  • Never reuse entropy bytes for two purposes: the quickstart takes bytes 0 to 31 for the key and bytes 32 to 43 for the nonce, and makes one key per request.
  • With AES-GCM, never encrypt two messages with the same key and the same nonce.
